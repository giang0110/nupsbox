# NupsBox Phase 2 P2.2 — Catalog & Content CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the Phase 1 read-only admin catalog/content surfaces into permission-aware operational CMS workflows without hard-delete, fabricated availability, or mutable published URLs.

**Architecture:** Keep server-rendered admin pages and authenticated Supabase server clients. Use Zod schemas for input validation, shared `can()` permissions from P2.1, database RLS for final enforcement, and database audit triggers for atomic non-secret mutation history.

**Tech Stack:** Next.js 16.3.3 App Router/Server Actions, React 19.3, TypeScript 5.9, Zod 4.6, Supabase/PostgreSQL/RLS, Vitest 5, pgTAP, Node `>=24.21.0 <25`.

**Spec:** `docs/superpowers/specs/2026-09-14-phase2-conversion-operations-design.md`

## Global Constraints

- P2.1 must be complete and green before starting P2.2.
- Do not use service-role credentials in browser or ordinary admin actions.
- `admin` and `staff` may create/update/publish catalog/content/media; only `admin` may update settings.
- `viewer` remains read-only.
- No CMS hard-delete UI is added in Phase 2.
- Published location/unit/blog slugs are immutable.
- `available_count` is not presented as real-time inventory; do not add CMS copy suggesting otherwise.
- Unverified prices remain nullable and render through the existing “Liên hệ” fallback.
- Public business settings only; deployment secrets remain environment variables.
- Every mutation must be audited without copying secret values into audit metadata.
